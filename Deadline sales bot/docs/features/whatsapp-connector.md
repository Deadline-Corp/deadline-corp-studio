# Фича: WhatsApp-коннектор (WAHA)

## Что делает
Подключает реальный номер WhatsApp к системе: принимает входящие (текст + голос),
показывает все переписки в панели, отправляет ответы. Работает с **рекламными
лидами** (click-to-WhatsApp, скрытый `@lid`).

## Файлы кода
- `channels/waha.py` — парсер вебхука (`parse_waha_webhook`), чтение истории, голос
  (`_download_waha_media` → Groq Whisper), `chat_id_from_waha_id`, **`resolve_lid_phone`** (@lid→телефон).
- `main.py`:
  - `/webhooks/waha` — приём (ACK 200 мгновенно), `/webhooks/greenapi` — запасной.
  - `_process_wa_payload` — фоновая обработка (семафор `_WA_INBOUND_SEMA`=3, своя сессия).
  - `_wa_send` — единая отправка (WAHA→Green-API→Cloud), с @lid-резолвом.
  - `_resolve_wa_chat_id` — находит реальный JID диалога из истории сообщений.
  - `_record_wa_operator_message` — запись ручных ответов с телефона (fromMe) + дедуп эхо.
- `services/whatsapp_sync.py` — импорт/сверка истории (reconcile).

## Как работает приём (ACK-first — КРИТИЧНО)
Вебхук отвечает **200 сразу**, тяжёлую работу делает в фоне через `_process_wa_payload`
(семафор 3, своя DB-сессия). Иначе при медленной обработке WAHA ретраит → бэклог →
пул соединений исчерпывается → процесс виснет (инциденты 06-15). **Правило: никакого
LLM, держащего request/DB-коннект; новые тяжёлые пути — в фон, bounded.**

## @lid — рекламные лиды (ГЛАВНОЕ)
Click-to-WhatsApp реклама шлёт лида под скрытым `@lid` (Linked ID), телефон скрыт
(privacy WhatsApp, by design). **Нельзя слать на `<lid-цифры>@c.us`** — уйдёт в
несуществующий чат, клиент не получит (WAHA вернёт 201).

**Решение (работает для большинства):** WAHA LID API `GET /api/{session}/lids/{lid}`
часто ЗНАЕТ реальный номер (`pn`). `resolve_lid_phone` достаёт его →
шлём на надёжный `<phone>@c.us`. Проверено: `205497189855465→+995571186100`,
`216067506983133→+66660748105`, `261813237248001→+77475973459`. Если `pn:null`
(анонимный) — шлём на `@lid` (best-effort, нестабильно).

На входящем `@lid` система резолвит телефон и сохраняет `customer.phone` → карточка
показывает номер (не «WhatsApp •хвост»), будущие отправки надёжны.

**Фундаментальный лимит:** 100% доставка рекламным лидам — только через официальный
WhatsApp Cloud API. Неофиц. WAHA/NOWEB на @lid by design нестабилен (Baileys
«Waiting for this message»). Резолв в реальный @c.us — лучший доступный путь.

## Голос
Входящие голосовые: WAHA отдаёт media (mime `audio/*`; тип в NOWEB пустой →
распознаём по mime). URL приходит как `localhost:3000` → переписываем на публичный
`waha_base_url`. Скачиваем → Groq Whisper → текст в переписку → мозг понимает.
Новые работают; история-синк голос пока не транскрибирует.

## Дубли (решено)
WAHA отражает наши же исходящие как fromMe → раньше писались как «оператор» (дубль).
`_record_wa_operator_message` пропускает эхо (совпадение текста с последними 8 репликами).

## Грабли
- История только при свежей привязке QR (reconnect → пусто). Backfill = ре-скан QR.
- Нативные авто-приветствия WhatsApp Business («Заполните форму») невидимы для WAHA.
- Неофиц. подключение → риск бана; держать запасной номер.

## Как проверить
- Статус сессии: `GET {waha}/api/sessions/default` → `status=WORKING`.
- Резолв @lid: `GET {waha}/api/default/lids/{lid}` → `pn`.
- Логи бота: `railway logs` → `POST /webhooks/waha 200`, `[wa-send] @lid → телефон`.
