# Журнал активности системы (Логи)

История работы приложения прямо в панели: **что / как / почему / кто**. Чтобы быстро
находить причины ошибок, изменений и событий, не копаясь в Railway-логах.

**Где:** Настройки → кнопка **«📋 Логи системы»** → страница `/logs` (только владелец).

---

## Что попадает в журнал

| Категория | Что логируется | Откуда |
|---|---|---|
| ⚙️ **config** | любое изменение конфигурации: воронка, поля, пресет, поведение, каналы, восстановление снимка, ручной чекпойнт — «кто что менял» | `config_snapshot.snapshot_now` (одна точка ловит все конфиг-правки) + ручной чекпойнт |
| ❗ **error** | НЕперехваченные ошибки в обработчиках (+ путь/метод), сбои обработки входящих WhatsApp | глобальный `@app.exception_handler(Exception)` + `_process_wa_payload` |
| 📤 **send** | итоги массовой отправки / пинка спящим: доставлено / ошибок / пропущено | `_run_send_sleeping_bg`, `_run_mass_nudge_bg` |
| 🤖 **bot** | оператор взял диалог на себя / вернул боту | `/conversations/{id}/takeover` |
| 🖥 **system** | запуск/деплой системы (версия + модель) — когда было обновление/рестарт | `startup` |

Каждая запись: время · уровень (info/warn/error) · категория · актор (bot / admin:&lt;имя&gt; /
operator / automation / system) · краткое описание · опц. `conversation_id` · `meta` (детали JSON).

## Где код

| Слой | Файл |
|---|---|
| Модель + таблица | `db/models.py:ActivityLog`, `alembic/versions/022_activity_log.py` |
| Запись + чистка | `services/activity_log.py` → `log_event(...)` (безопасная, не роняет логику), `prune(days=30)` |
| Чтение (API) | `admin_api.py` → `GET /admin/api/logs` (owner-only): фильтры `category/level/q/conversation_id`, курсор `before`, сводка `cat_counts_24h` + `errors_24h` |
| UI | `admin-ui/src/pages/Logs.tsx` (фильтры, цвет по уровню, раскрытие `meta`, переход в карточку лида, авто-обновление 15с, «Показать ещё») |
| Точки логирования | `config_snapshot.snapshot_now`, `main.py` (exception handler, `_process_wa_payload`, `startup`), `admin_api.py` (mass-send, takeover, ручной чекпойнт) |

## Свойства

- **Не ломает бизнес-логику:** `log_event` глотает любые свои сбои — журнал вспомогательный.
- **Хранение 30 дней:** `prune` в кроне (`run_wa_maintenance`) — таблица не растёт без предела.
- **Только владелец:** журнал может содержать чувствительное «кто что менял».
- **Курсор-пагинация** по времени (`before`) + фильтры + поиск по тексту.

## Как добавить новое событие

```python
from services.activity_log import log_event
log_event("send", "Краткое описание события", level="info", actor="operator",
          conversation_id=conv.id, customer_id=cust.id, meta={"любые": "детали"})
```

Категории: `config | channel | stage | bot | send | task | auth | error | lead | system`
(можно свободную строку — она появится фильтром в UI).
