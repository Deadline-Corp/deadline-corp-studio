# Кастом-поля под нишу + авто-заполнение ботом

Поля карточки клиента (тип проекта, бюджет, срок, услуга, цель…) — **под нишу**.
У клиники одни, у веб-студии другие, у фитнеса третьи. Бот их **сам читает** (учитывает
в ответах) и **сам заполняет** из переписки, не затирая ручные правки оператора.

## Два слоя

### Слой 1 — НАБОР полей (схема), под нишу
Поля определяются **пресетом ниши** — `NICHE_PRESETS` в [admin_api.py](../../admin_api.py)
(ключ `fields` у каждого пресета). При применении пресета (`POST /presets/{key}/apply`)
создаются `CustomFieldDef` (key/label/field_type text|number|select/options/position).
Примеры:
- веб-студия: `project_type` (select), `budget`, `deadline`
- стоматология: `service` (select), `complaint`, `preferred_time`
- фитнес: `goal` (select), `experience` (select), `preferred_time`

**Править вручную:** Настройки → редактор полей (`GET/POST /custom-fields`, bulk-replace
как стадии). Значения у лидов (`profile_data['fields']`) не теряются — вернёте поле с тем
же `key`, значения снова видны.

Модель: `CustomFieldDef` ([db/models.py](../../db/models.py)). Значения живут в
`customers.profile_data['fields'][key]` — без миграций на каждое новое поле.

### Слой 2 — ЗАПОЛНЕНИЕ значений, авто из переписки
Решающий мозг (`conversation_brain.analyze_and_advance`) на каждом сообщении и так делает
**один** LLM-вызов. Он **заодно** извлекает значения полей ниши из того, что лид уже сказал
(поле `extracted_fields` в том же JSON — без второго вызова). Где код:
[services/conversation_brain.py](../../services/conversation_brain.py) —
`_field_specs` (список активных полей → в промпт), `_fields_spec_block` (инструкция «заполни
ТОЛЬКО явно названное, не выдумывай»), `_merge_auto_fields` (запись с защитой).

**Защита ручных правок (главное):** `profile_data['fields_auto']` = множество ключей,
заполненных **ботом**. Правило слияния:
- пишем значение только если поле **пустое** ИЛИ ранее заполнено **самим ботом** (ключ в `fields_auto`);
- как только оператор правит поле вручную (`POST /conversations/{id}/fields`,
  [admin_api.py](../../admin_api.py) `conversation_fields_save`) — ключ **уходит** из
  `fields_auto` → бот это поле больше **не трогает**. Твоё слово всегда главнее.
- выдуманные ботом ключи (не из активных полей) и пустые значения — игнорируются.

**Стиль переписки не страдает:** Слой 2 только ЧИТАЕТ переписку и заполняет поля — он не
меняет текст ответа. Бриф бот и так собирает естественно (тип задачи → «от $X» → созвон);
поля заполняются из этого разговора, без отдельного «допроса».

## Настройка
- `auto_fill_fields` (bot_settings, деф. **ВКЛ**) — выключить авто-заполнение.
- Поведение безопасно по умолчанию: только пустые/авто-поля, ручное не перетирается.

## Где бот ИСПОЛЬЗУЕТ поля
Отвечающий мозг (`wa_drafts._client_card`) подмешивает заполненные поля в промпт как
«ИЗВЕСТНО О КЛИЕНТЕ (не переспрашивай уже известное)» — бот не задаёт вопросы про то,
что уже знает. См. [reply-engine-drafts.md](reply-engine-drafts.md).

## Тесты
`notes/_test_autofields.py` — 7 проверок защиты: пустое→заполнил, ручное защищено,
авто обновляется, выдумка игнор, пустое игнор, None безопасно, формат spec-block. Все PASS.

## Грабли
- Поля под нишу = СХЕМА (видна в каждой карточке, CRM-зеркале, экспортах). Поэтому Слой 1
  через пресет/редактор (стабильно), а не «бот создаёт поля на лету» (дало бы дубли/дрейф).
- `extracted_fields` приходит из LLM → `_merge_auto_fields` фильтрует по списку активных
  ключей и обрезает значение до 200 символов (анти-мусор).
