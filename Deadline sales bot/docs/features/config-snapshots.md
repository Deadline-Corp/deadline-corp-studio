# Снимки конфигурации — откат на любую версию

Версионирование настроек системы: можно вернуться на любую прошлую конфигурацию, не
теряя данные лидов. Закрывает пробел — раньше откат был только у промпта; воронка/поля/
автоматизации/`bot_settings` менялись безвозвратно, а смена пресета молча «сиротила» карточки.

---

## Что снимок содержит

Бандл конфиг-таблиц в одной JSONB-строке (`config_snapshots.payload`, миграция **021**):

| Секция | Источник | Восстановление |
|---|---|---|
| `funnel_stages` | `funnel_store.get_stages` | `funnel_store.save_stages` (полная замена) |
| `custom_fields` | `CustomFieldDef` | delete + re-insert |
| `automations` | `AutomationRule` | delete + re-insert (история `automation_runs` каскадно обнуляется) |
| `bot_settings` | `bot_settings.get_all` | `set_many` (ключи снимка ставятся, остальные стираются → дефолт) |
| `system_prompt` | `prompt_store.get_active_system_prompt` | `set_active_system_prompt` (или `deactivate_all`) |

**Восстановление трогает ТОЛЬКО эти таблицы.** Переписки, клиенты, сообщения, задачи, брони —
не затрагиваются. Откат — это откат НАСТРОЕК, а не данных.

## Когда снимок берётся

- **Авто (`reason="auto:..."`)** — ПЕРЕД каждым конфиг-меняющим действием: сохранение/сброс
  воронки, сохранение полей, применение пресета, изменение поведения, перед самим откатом.
  Берётся через `snapshot_now()` (своя короткая сессия — не мешает самой операции; сбой снимка
  не роняет действие).
- **Ручной (`reason="manual"`)** — кнопка «💾 Сохранить чекпойнт» в Настройках.

Промпт НЕ триггерит авто-снимок отдельно (у него своя история версий в `prompt_versions`).

---

## Как пользоваться (UI)

Настройки → карточка **«🗂 Версии конфигурации · откат»**:
- **Сохранить чекпойнт** — снять текущую конфигурацию (с названием).
- Список версий: дата · причина · счётчики (воронка N · поля N · авто N).
- **↩︎ Восстановить** → подтверждение → откат. Перед откатом система берёт авто-снимок
  текущего состояния (можно откатить откат).

---

## Безопасность отката

- Восстановление **по секциям**, каждая в try/except → сбой одной секции не отменяет другие;
  ответ содержит `restored` (что применилось) и `errors` (что не удалось).
- Воронка: `save_stages` требует наличие builtin-ключей — снимок их всегда содержит (берутся из
  `get_stages`), так что замена безопасна.
- Автоматизации: полная замена обнуляет `automation_runs` (дедуп-историю) — правила могут
  сработать заново на тех же лидах. Приемлемо для редкого осознанного отката.

## Грабли

- `bot_settings.set_many` и `prompt_store` коммитят в СВОИХ сессиях (не в транзакции запроса) —
  поэтому restore этих секций применяется отдельно от funnel/fields/automations. Для осознанного
  отката это ок; полная атомарность всех пяти секций — задел на будущее.
- Снимки не чистятся автоматически (хранение дешёвое, JSONB; правило never-delete). Прунинг
  старых авто-снимков — отдельная будущая опция.
