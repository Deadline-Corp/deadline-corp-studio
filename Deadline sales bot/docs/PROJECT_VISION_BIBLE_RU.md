## 1. ЧТО ЭТО (одним абзацем)
Умная самонастраиваемая **система управления продажами на базе агентов** — своя гибкая
CRM/Sales-OS. Бот общается с лидами во всех каналах (сайт/Telegram/WhatsApp/Instagram),
сам ведёт их по воронке до целевого действия (созвон/встреча/запись/расчёт), напоминает,
греет, ставит задачи, отражает всё в визуальной панели и CRM, а сложное — передаёт
человеку. Настраивается под **любую нишу без кода**: владелец проходит онбординг,
«вываливает» инфо о бизнесе → агент сам раскладывает по мозгам/знаниям/воронке.

## 2. ДЛЯ КОГО
- **DEADLINE** (веб-студия) — наш боевой инстанс, живой трафик. Эталон.
- **Free-пилоты (товарищи)** — Кирил (клининг + ремонт/реновации), далее психолог,
  и др. ниши. Бесплатно, за фидбэк. Потом, возможно, продукт на продажу.
- Принцип: продажи везде ~одинаковы (лид → квалификация → целевое действие → закрытие);
  ниша задаёт нюансы (воронка, тон, прайс, скрипты). → несколько шаблонов + ручная
  донастройка.

## 3. АРХИТЕКТУРНОЕ РЕШЕНИЕ (выбрано)
- **Мультитенант-апп для всех пилотов** (один Railway-проект) + **Neon free Postgres**
  (~$5-7/мес за всех). Новый клиент = новая конфигурация, без нового деплоя, управление
  из одной супер-админки. (Обоснование цены — в MULTITENANT_ONBOARDING_PLAN_RU.md §5.)
- **DEADLINE — отдельный проект** (живой, не трогаем экспериментами).
- Одна кодовая база на всё.

## 4. ПРИНЦИПЫ (не нарушать)
1. **Жёсткие гарантии — в КОДЕ, не в промпте** (llama/LLM ненадёжно слушает prose).
2. **Postgres = источник правды; CRM/панель — отражение.** Не блокируем ответ лиду.
3. **Self-service:** владелец настраивает сам по инструкции; мы — не в цикле.
4. **Дёшево и из одного места:** мультитенант, общая супер-админка.
5. **Безопасность живого бота:** рискованное — за флагом/на копии, не на боевом.
6. **Агент — узкий и управляемый** (tool-use + ревью), не автономный «делает всё».

## 5. ЧТО УЖЕ ПОСТРОЕНО (7 волн, в проде DEADLINE)
Мозг-мультипровайдер (+Gemini), WhatsApp-коннектор, каналы→настройки, мгновенный
триггер «стадия изменилась», умная карточка (ленивые сделки+контакт, дедуп, авто-merge),
ICS-календарь, AI-копилот оператора «🧭 Что делать». Бот уже агентен: бронь, задачи,
воронка, followup, советы. Детали — PROJECT_MASTER_RU.md.

## 6. КЛЮЧЕВОЙ USE-CASE: КИРИЛ (формирует требования)
У одного тенанта — **НЕСКОЛЬКО продуктов = несколько воронок**:
- **Клининг:** квалифицировать (реально ли нужен клининг) → договориться о встрече/
  замере → расчёт (стандартный) → согласовать время → подтвердить занятость команды
  (из календаря) → поставить в календарь → команда клинеров видит и едет в день X →
  клиенту несколько напоминаний ДО приезда («едем, всё в силе») → перенос если просит →
  upsell/перевод в постоянного клиента.
- **Ремонт/реновации:** организовать встречу → выезжает кто-то из команды или сам
  Кирил → для крупного клиента — **эскалация/передача общения** конкретному человеку.
Следствия для системы (новые требования):
- **Мульти-воронка на тенант** (бот сначала определяет продукт → ведёт по его воронке).
- **Команда и маршрутизация:** назначение исполнителя (бригада клинеров / выездной /
  Кирил), эскалация крупных, уведомления назначенным.
- **Календарь→команда:** бронь привязана к доступности команды; назначенные видят свои выезды.
- **Серии напоминаний** клиенту до визита + обработка переноса.
- «**Очень умный администратор**»: понимает контекст, постоянных клиентов, когда шутят/
  спамят, когда передать человеку.

## 7. ОНБОРДИНГ (выбранный подход — гибрид)
Минимум обязательного + богатый «дамп»:
- **Короткие шаги:** выбрать шаблон ниши (старт-воронка), цель бота, каналы, часы.
- **«Расскажите о компании» (дамп):** вставить/загрузить текст сайта + регламенты +
  прайсы, опц. ссылка (агент скачает), опц. **голос** (надиктовать — транскрипт Whisper).
- **Конфиг-агент** переваривает дамп → раскладывает: тон/оффер → Мозг; услуги/цены/FAQ →
  Знания (KB); ниша → Воронка; часы/цель → Настройки. Возвращает **черновик на ревью**.
- **Услуги живут в Знаниях (KB), не отдельным каталогом** (по решению пользователя):
  обновление = пере-загрузить/поправить док → агент пере-выделит. Продукты меняются легко.
- После онбординга — **spotlight-тур под цель ниши** (где что настраивать).

## 8. ГРАНИЦЫ (scope — чтобы не дрейфовать)
- **В работе/ближайшее:** мультитенант-апп, онбординг+конфиг-агент, мульти-воронка,
  команда/маршрутизация, WhatsApp (на наших ключах), тур под нишу.
- **Отложено (по решению):** браузер-агент (отдельный opt-in сервис, не в живой бот);
  полноценный биллинг/продажа; продвинутая аналитика. Ключи клиентов — позже (сейчас наши,
  но с лёгким переключением).
