# DEADLINE — WhatsApp в системе: как устроено, состояние, эксплуатация

_Актуально на 2026-06-15. Этот документ — единая точка правды по WhatsApp-части
бота: что подключено, откуда берутся данные, по какой логике лиды попадают в
стадии воронки, какие есть ограничения и как всем этим пользоваться._

---

## 1. Цель и текущий охват

Бот DEADLINE — единая система обработки лидов из всех каналов (сайт-виджет,
Telegram, Instagram/Messenger, **WhatsApp**) в одной панели «Переписки» + воронка.
По WhatsApp задача: видеть **все** переписки номера, понимать **кто на какой
стадии**, предлагать ответы, и не писать клиентам без ведома оператора.

Состояние на 2026-06-15: **63 диалога** в системе — 53 WhatsApp + 10 сайт.

---

## 2. Архитектура WhatsApp-подключения

Официальный WhatsApp Cloud API не подошёл (нужна верификация бизнеса, недоступна).
Поэтому — **self-hosted WAHA** (`devlikeapro/waha`, неофициальная обёртка над
Baileys) на своём Contabo VPS (`84.247.148.135:3000`, Docker, движок NOWEB).
Номер привязан как «связанное устройство» по QR — без верификации, без лимитов
на чаты, $0 за софт.

Поток данных:

```
WhatsApp (телефон)
   │  связанное устройство (QR)
   ▼
WAHA (VPS, NOWEB + store)
   │  webhook message.any           ─────► /webhooks/waha  (НОВЫЕ входящие, онлайн)
   │  REST /chats, /chats/{id}/messages ─► sync_waha_history (ИСТОРИЯ, по кнопке)
   ▼
DEADLINE бот (Railway): Customer + Conversation(channel=whatsapp) + Message
   │
   ▼
Панель «Переписки» + воронка + классификация лид/не-лид + стадия
```

Ключевые файлы:
- `channels/waha.py` — парсер вебхука + чтение истории (chats/messages/session) +
  `normalize_waha_history_message`, пометка `@lid` vs телефон (`wa_peer_type`).
- `services/whatsapp_sync.py` — `sync_waha_history()`: идемпотентный импорт чатов
  и сообщений (дедуп по `waha_id`, реальные таймстампы) + классификация + **сверка**.
- `services/lead_classifier.py` — `classify_whatsapp_conversation()`: лид/не-лид +
  категория + температура + **стадия воронки** (LLM Gemini + эвристика-фоллбэк).
- `main.py` — `/webhooks/waha`, единая отправка `_wa_send` (приоритет WAHA), приём
  входящих с заполнением имени/номера; режимы наблюдения/черновика.
- `admin_api.py` — эндпоинты `/whatsapp/sync`, `/whatsapp/status`,
  `/whatsapp/import-leads`, `/conversations/*` (карточка, кнопки).

## 3. Откуда столько диалогов (источники данных)

Три источника, как WhatsApp-диалоги попали в систему:

1. **Мета-реклама (Instagram/Facebook click-to-WhatsApp)** — ОСНОВНАЯ масса (~44).
   Люди жмут рекламу DEADLINE → открывается WhatsApp → пишут на номер. В метаданных
   таких сообщений виден `externalAdReply`. Это **реальные рекламные лиды**, не мусор.
2. **Импорт 8 разобранных лидов** из прошлой сессии-анализа (Fable) — с готовыми
   ответами, стадиями и демо. Заведены через `/whatsapp/import-leads` по телефону.
3. **Живые входящие** после подключения — падают через веббук автоматически.

> Поэтому «потянулось много» — это и есть твой рекламный поток в WhatsApp.

## 4. Воронка и статусы — СОГЛАСНО ЧЕМУ

### Стадии (`lead_stage`, активные builtin)
`new_lead` 🆕 → `in_dialog` 💬 → `qualified` ✅ → `on_call` 📞 → `proposal` 📄 →
`prepayment` 💰 → `completed_won` 🏁 · и `lost` ❌ (с причиной).
(Определены в `services/funnel_store.py::BUILTIN_STAGES`; legacy-ключи `nda/
tz_approved/in_work/post_sale` — из старых строк, в UI не используются.)

### Как присваивается стадия
- **Импортным 8 лидам** — стадия задана вручную из разбора (`on_call` для тех, с
  кем договорились созвониться в понедельник, `qualified`, `in_dialog` и т.д.).
- **Синхронизированным (рекламным) лидам** — стадию назначает **классификатор по
  содержанию переписки** (Gemini): «договорились созвониться» → `on_call`, чётко
  описал задачу → `qualified`, идёт диалог → `in_dialog`, отказ/спам → `lost`,
  только написал → `new_lead`. Применяется ТОЛЬКО к дефолтному `new_lead` —
  курированные/ручные стадии не перетираются.
- **Живой трафик** — бот двигает стадии сам по ходу диалога в CRM-режиме
  (`services/funnel.py`), оператор может сменить вручную (кнопка «Сменить стадию»).

### Температура (`lead_temperature`): `cold/warm/hot/ready/client/frozen`
Назначается по сигналам в сообщениях (ключевые слова «готов», «срочно» → hot/ready;
N содержательных ответов → warm) и остывает при молчании (decay 14/21 дн.).
Логика — `services/temperature.py`. При импорте/классификации только повышается.

## 5. Кнопки карточки диалога (все рабочие)

| Кнопка | Что делает |
|---|---|
| 👤 Взять на себя / 🤖 Вернуть боту | Оператор перехватывает диалог (бот молчит) и обратно |
| Сменить стадию… | Ручной перевод по воронке (пишет историю переходов) |
| ⚡ Пинок | Сгенерить черновик от LLM или отправить «дожим» сразу |
| 📋 Задача | Поставить задачу (себе/боту) |
| 🧭 Что делать | LLM-подсказка следующего шага + черновик |
| 🔁 Регулярный | Повторяющийся клиент (расписание касаний) |
| 📋 Назначить на… | Назначить лида на сотрудника (если есть команда) |
| ✅ Отправить / 🚫 Отклонить | Одобрить/отклонить предложенный ботом ответ (WhatsApp) |
| 🤖 Разрешить боту вести диалог | Бот отвечает этому лиду сам (override наблюдения) |
| Отправить (поле ответа) | Ручной ответ оператора лиду в его канал |

Режим по умолчанию для WhatsApp — **наблюдение**: бот видит и предлагает, но сам
клиенту НЕ пишет, пока оператор не нажмёт ✅ или не разрешит автономку.

## 6. Сверка «панель = WhatsApp» (reconcile)

Источник правды — WAHA (что видит привязанное устройство). Кнопка «🔄 Подтянуть
все переписки» запускает `sync_waha_history(reconcile=True)`:
- импортирует новые сообщения из WAHA (дедуп по `waha_id`);
- удаляет **фантомные** локальные сообщения бота (сгенерированные, но не ушедшие
  в WhatsApp) — чтобы база не показывала того, чего в мессенджере нет;
- **сверяет** число WhatsApp-сообщений в базе и в WAHA по каждому чату
  (`chats_matched` / `chats_mismatched`).

## 7. Ограничения (важно, честно)

1. **`@lid` не резолвится в телефон.** Рекламные лиды WhatsApp отдаёт под скрытым
   идентификатором `@lid` (WAHA возвращает `pn: null`). Поэтому такие чаты нельзя
   автоматически склеить по номеру с импортированными-по-телефону лидами → у части
   из 8 импортных есть «двойник» под `@lid` (напр. Бегайдар). Дедуп — только по
   имени (нечётко) или вручную.
2. **Нативные авто-приветствия WhatsApp Business невидимы.** Сообщения вида
   «Добро пожаловать! Заполните форму» из рекламы шлёт сервер Meta мимо привязанного
   устройства — WAHA их не видит, синхронизация не подтянет. Только офиц. WhatsApp
   Business API.
3. **История только активных чатов.** WhatsApp при свежей привязке отдаёт недавнюю
   историю, не «всё за всё время».
4. **Неофициальное подключение** (WAHA) — есть риск бана номера; для основного
   номера держать запасной.

## 8. Эксплуатация (шпаргалка)

- **Подтянуть/сверить переписки:** панель → Каналы → WhatsApp → «🔄 Подтянуть все
  переписки» (делает импорт + сверку + распределение по стадиям).
- **Полный backfill истории:** нужен один ре-скан QR (logout сессии WAHA → скан в
  WhatsApp → Связанные устройства). После — кнопка синка.
- **Режим бота по WhatsApp:** Каналы → WhatsApp → 👀 наблюдение / 📝 черновик / 🤖 авто.
- **Мозг бота:** сейчас **Gemini 2.5 Flash** (`LLM_PROVIDER=gemini`). Откат —
  убрать переменную (вернётся OpenRouter llama). Дешевле — `gemini-2.5-flash-lite`.
- **Деплой:** `railway up` на service `9cdf9db1` (env production); GitHub-пуш сам
  не деплоит. Миграции применяются на старте (`alembic upgrade head`).

## 9. Что осталось (бэклог)

- `@lid → телефон` маппинг + дедуп импортных лидов с рекламными двойниками.
- Авто-архивация не-лидов (личное/спам), чтобы не мелькали в активной воронке.
- Авто-пересверка по расписанию (cron), чтобы панель всегда была свежей.
- Решение по нативным авто-приветствиям (офиц. WhatsApp Business API — если нужно).
